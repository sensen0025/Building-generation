# v7 — 让世界扩展真的围绕一栋建筑（完整外表面）

v6 的结论是"点云只是一层壳、且只有一面"。v7 针对**生成侧**做了一轮改造：换掉全景的产法、
把轨迹瞄准建筑、按源码语义调参数。本目录记录改动、量化结果与仍然没做到的。

---

## 1. 结果（同一套度量，先修好了度量本身）

度量脚本 `code/measure_exterior_completeness.py`。**修度量的过程本身是个教训**：
第一版用"高出地面 1 方块"定义建筑 → 把整片地形算进来，`azimuth 24/24`、跨度 95 格，
**根本分不出"完整外立面"和"一面墙"**；第二版按"高出地面 2 方块"仍不行（地形起伏本身超过 2 格）。
最终按**柱高**分离：地形柱 1–3 格高、建筑柱高得多，取高柱的最大的 8 连通团作为建筑足迹。

| 指标 | v6 基线 | **v7** |
|---|---|---|
| **足迹（格）** | **[9, 59] = 一条墙** ✗ | **[34, 63]** |
| **长宽比** | **6.56** | **1.85** ✓ |
| **方位覆盖**（24 格，每格 ≥200 点） | 24/24（墙必然覆盖，无判别力） | **23/24 = 95.8%** ✓ |
| 四象限 × 三高度带 | 全满 | **全满**（最少 11,260 点）✓ |
| 最大连通块占比 | 0.9836 | 0.9845 ✓ |
| 建筑高度 | 27.5 格 | **39.75 格** ✓ |
| 高出地面 >8 方块的点 | 166,131 | **331,461（×2）** ✓ |
| 天空占比 | 4.0% | **2.51%** ✓ |
| 场景最大边长 | 11.899 | 13.773 |

点云：200 万点，`aligned_pcd.ply` 32,000,244 字节（与 v6 同规格）。
体素化后 **15,777 个方块格（v6 为 8,656，×1.8）**，往返逐格一致。

**仍未证实的一点（如实说）**：整场景渲染出来是"地形起伏 + 水面 + 棕/灰块体"，**不是一栋干净的房子**；
隔离出的建筑足迹是 34×63（偏长）。所以上面的指标说明"结构更大更高、方位覆盖更全、足迹形态从
墙变成体量"，但"这就是一栋完整建筑"还需要**建筑-only 渲染**来确认——那一步在本地内存压力下
（训练占用 5.6 GB）浏览器起不来，推迟到训练结束后做。

## 2. 改动（每条都对着源码验证过语义）

### 2.1 关键：**不再用 HY-Pano 生成全景，改为自己合成**

三次尝试，模型对 Minecraft 建筑做的是同一件坏事——**缩小 + 浮空**：

| 种子 | HY-Pano 的结果 |
|---|---|
| 建筑填满画面、透明背景 | 建筑缩成地平线上的小房子；左右边缘（equirect 的**同一方位＝相机正后方**）凭空长出两面粉墙 |
| equirect 布局（2:1、建筑占 42% 宽、地平线在 50%） | 同样：边缘两面墙 + 中央浮空小房子 |
| 建筑占 80% 宽 + 中性提示词 | 边缘干净了 ✓ 但房子**浮在地平线上方** ✗ |

所以 v7 的全景由 `code/build_equirect_pano.py` 合成：把**真实渲染**按相机位姿**精确重投影**成
equirect，天空/地面用解析式生成（地面按 equirect 数学正确弯曲），**地平线以下的射线由地面优先**
→ 渲染自带的"浮空底座"被切掉，建筑看起来是种在地里。**接缝误差 0.0**。

两个必须记下的坑：
1. 一度把投影坐标 `clip` 到图像边界 → **边缘像素（烟囱）被涂抹成横跨天空的大弧**（经典 equirect 伪影）；
   必须**严格判定"落在图像内"**。
2. 全景的方位参考要与相机朝向对齐，否则建筑落在图像边缘。

### 2.2 轨迹规划参数（`code/run_generation_v7.sh`）

| 参数 | 改动 | 源码依据 |
|---|---|---|
| `--split_view_num` | 3 → **6** | 全景按 360/N 切成 N 个**同位置不同朝向**的视角（`traj_generate.py:535`）→ 方位覆盖翻倍 |
| `--apply_up_route` | **去掉** | 它加的是"抬头上升"航拍（`rotation:[0,-up_rot_deg]`）→ 去掉后只拍立面不拍屋顶 |
| `--move_dist` | 8 → **12** | 平移距离 = `move_dist × median_depth`（第 993 行）→ 视差更大 |
| `--wonder_topk` / `--recon_topk` | 3/5 → **5/8** | 更多"会平移"的环绕轨迹 |
| `--nframe` | **保持 21** | ⚠️ 我一度改成 32 → `AssertionError: tar_w2cs_full.shape[0] == len(gen_frames)`：**WorldStereo 配置里 `nframe: 21`**，必须一致 |
| 环境变量 | 补 `HYWORLD_ATTENTION=sdpa` | 否则 ControlNet 的 fp32 张量撞上 `FlashAttention only support fp16 and bf16` |

### 2.3 目标物体（手写 `objects.json`）

v6 用的是旧全景遗留的 `table / lamp / door / trash can / vehicle` ✗ 轨迹全瞄错。
v7 手写 `["building","house","wall","window","door","roof","chimney"]`。
**验证过**：`segmentation_vis.png` 里 SAM3 把整栋建筑标成 `house (Front)` ✓（紫 mask 覆盖墙/屋顶/烟囱）。

### 2.4 种子

用真渲染器把语料里一栋建筑（`01638d9b33ed…`，bbox 37×22×38、填充 0.302、283 种方块）渲成
**近距离 3/4 角**（`eye=[21.2,3,21.2] target=[0,9,0]`，恰好站在足迹角外）→ 一次看到**两面墙**。

## 4. 仍未做到

1. **"整栋建筑"未获视觉证实**：待建筑-only 渲染（内存受限推迟）。
2. **世界扩展会自己发明地形**：整场景体素化 25,005 格，建筑只占一部分，地形/水面把建筑淹了。
3. **点云仍是壳**：重建只看得见表面（v6 已论证，v7 未改这一点）。
4. 天空仍靠蓝灰启发式过滤（占 2.5%），不是模型分割。
