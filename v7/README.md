## 1. 视觉结论（这是验收结果）

`work/v7_building_render.png`（隔离出的建筑，六视角，918,580 点，我看过）：

- **俯视是一个 V 形/角状足迹 = 两面墙的转角**，不是封闭建筑；
- 正/侧视是一堵**高而薄**的墙，四周**大量弥散雾状点**；
- 整场景渲染 `work/v7_full_scene_4views.png`：世界扩展**自己发明的地形 + 水面**占主体，建筑被淹。

⇒ **不合格**。与 v6 相比只是"一面墙"变成"两面墙的转角"，离"完整建筑外表面"仍很远。

## 2. 根因（代码 + 计算，可复核）

**① `move_dist` 的语义被我理解错了。** `src/navi_utils.py:2350`：

```
def process_trajectories(trajectories, D, X, ...):
    D: Maximum path length; truncate fitted curves longer than D.   ← D 是"相机总共走多远"
    X: Number of uniformly sampled output points.                    ← X = nframe
```

调用方 `traj_generate.py:993/997`：
```
move_threshold = move_dist * global_median_depth * 1.5   # reconstruct 任务
```
所以 **`move_dist` 是"路径长度 = 多少倍中位深度"**，不是"每步走多远"。
我从 8 调到 12，等于**命令相机走得更远** ✗

**② 我这张合成全景的深度统计**（相机眼高 3、地面解析平面、equirect 均匀采样）：地面占 50% 像素，
**深度中位数 4.24 单位**；而我把渲染相机放在半径 **30** 单位处 → 建筑距离 = **7 倍中位深度**，
在世界尺度下是个"远处的离群物体" ✗

**③ 于是路径长度**：
```
move_dist=12 → 12 × 4.24 × 1.5 = 76 单位 = 建筑距离的 2.5 倍   ✗✗
move_dist=8（官方默认）      = 51 单位 = 1.7 倍                ✗
```
相机被命令走 1.7–2.5 倍于建筑距离的路程 → 几步就飞过建筑，后半段全在拍**扩展发明的地形** ✓✓

**这同时解释了 v6 与 v7 两次都是"薄墙"**：v6 用的官方默认 `move_dist 8` 已经是 1.7 倍 ✗。
`look_at_target` 只保证相机*看着*建筑，**不保证它离得近** ✗

## 3. 诊断数字（**不足以作为验收**，只用于解释上面的图）

度量脚本 `code/measure_exterior_completeness.py`。修度量本身也踩了两次坑：
第一版按"高出地面 1 方块"定义建筑 → 把整片地形算进来（`azimuth 24/24`、跨度 95 格，
**分不出"完整外立面"和"一面墙"**）；第二版按"高出地面 2 方块"仍不行（地形起伏本身超过 2 格）。
最终按**柱高**分离（地形柱 1–3 格、建筑柱高得多，取高柱的最大 8 连通团）。

| 数字 | v6 | v7 | 说明 |
|---|---|---|---|
| 隔离足迹（格） | [9, 59] | [34, 63] | v6 是直墙，v7 是转角——都**不是封闭建筑** ✗ |
| 足迹长宽比 | 6.56 | 1.85 | **曾被我当成"进步"**，但看图只是 V 形转角 |
| 建筑高度 | 27.5 格 | 39.75 格 | 更高，但**更薄** |
| >8 方块点数 | 166,131 | 331,461 | 结构更多，但**空间分布仍然是墙** |
| 天空占比 | 4.0% | 2.51% | ✓ 这一条是真的改善 |
| 整场景体素格 | 8,656 | 15,777 | 多出来的部分是**地形/水面**，不是建筑 ✗ |

**教训**：这些数字没有一个能替代"看图"。尤其"足迹长宽比"——它给我的 1.85 是**算法隔离出来的区域**
的形状，而我**没有先用图确认那个隔离结果本身**。
